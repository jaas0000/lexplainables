# Story 017: 2FA (TOTP)

**Prioriteit:** laag
**Story points:** 3
**Service:** `api/` + `frontend/`
**Afhankelijkheid:** story 016 (account-pagina), story 015 (email-kolom aanwezig)

## Verhaal

Als ingelogde gebruiker wil ik een TOTP-authenticator-app (zoals Google Authenticator of Authy) aan mijn account kunnen koppelen, zodat mijn account beschermd is tegen wachtwoord-diefstal met een tweede factor.

## Acceptatiecriteria

- [ ] Een gebruiker kan 2FA starten via `/account`; de API geeft een `otpauth://`-URI terug die de frontend als QR-code toont.
- [ ] De gebruiker bevestigt de koppeling door één geldige TOTP-code in te voeren; daarna is 2FA actief.
- [ ] Na activatie vereist het inloggen een geldig 6-cijferig TOTP-code na het wachtwoord (tweestapslogin).
- [ ] Een gebruiker kan 2FA uitschakelen door één geldige code in te voeren; daarna is het account weer wachtwoord-only.
- [ ] Het TOTP-secret wordt versleuteld opgeslagen via Fernet (`shared/crypto.py`); de plaintext verlaat de API nooit na de koppel-stap.
- [ ] Als er geen `FERNET_KEY` geconfigureerd is, weigert de API het koppelen met een 400.
- [ ] `GET /v1/auth/me` (story 016) geeft `totp_ingeschakeld: true` terug zodra 2FA actief is.
- [ ] De login-flow retourneert een `code: "totp_required"` zodra het wachtwoord klopt maar 2FA nog nodig is; de BFF toont dan een tweede invulscherm voor de TOTP-code.

## Schemabeslissing

**Alembic-migratie:** voeg `totp_secret_enc TEXT` (nullable) en `totp_ingeschakeld BOOLEAN NOT NULL DEFAULT FALSE` toe aan `gebruikers` (migrations/0005_*).

**Python-models (`api/app/features/identiteit_toegang/models.py` uitbreiden):**

- `TotpBeginResultaat` — `otpauth_uri: str`
- `TotpCodeVerzoek` — `totp: str` (max 16)
- Uitbreiding `VerifyResult` (bestaand model) — voeg `code: str = ""` toe (`""` | `"invalid"` | `"totp_required"`)

**Endpoints:**

| Endpoint | Methode | Doel | Auth |
|---|---|---|---|
| `/v1/auth/2fa/begin` | POST | Start 2FA-koppeling, geeft `otpauth://`-URI | `vereist_api_token` + `X-User-Id` |
| `/v1/auth/2fa/activeer` | POST | Bevestig koppeling met geldige TOTP-code | `vereist_api_token` + `X-User-Id` |
| `/v1/auth/2fa/uitschakel` | POST | Schakel 2FA uit met geldige TOTP-code | `vereist_api_token` + `X-User-Id` |

**BFF-routes (`frontend/app/api/`):**

| Route | Methode | Doel |
|---|---|---|
| `app/api/auth/2fa/begin/route.ts` | POST | Proxy → `/v1/auth/2fa/begin` |
| `app/api/auth/2fa/activeer/route.ts` | POST | Proxy → `/v1/auth/2fa/activeer` |
| `app/api/auth/2fa/uitschakel/route.ts` | POST | Proxy → `/v1/auth/2fa/uitschakel` |

## Edge cases

- `FERNET_KEY` ontbreekt → `POST /v1/auth/2fa/begin` geeft 400 "Geen FERNET_KEY geconfigureerd; 2FA kan niet worden opgeslagen."; frontend toont foutmelding.
- Ongeldige TOTP-code bij activeren → API 400; gebruiker mag het opnieuw proberen.
- Ongeldige TOTP-code bij uitschakelen → API 400.
- Account niet gevonden (verwijderd terwijl sessie nog geldig was) → API 404; BFF redirect naar `/login`.
- 2FA koppelen zonder eerst `begin` te roepen (geen pending secret) → API 400 "Geen 2FA-setup in uitvoering.".
- Inloggen zonder TOTP terwijl 2FA aan staat → API retourneert `code: "totp_required"`; BFF toont een tweede invulscherm.
- Verkeerd wachtwoord + 2FA aan → `code: "invalid"` (TOTP-status niet lekken via de error).

## Auth / rollen

- `POST /v1/auth/2fa/begin`, `/activeer`, `/uitschakel` — achter `vereist_api_token` + `X-User-Id` (identiteit uit de Auth.js-sessie).
- Geen rolbeperking — elke ingelogde gebruiker kan 2FA beheren op zijn eigen account.
- `POST /v1/auth/verify` — al beschikbaar (story 006); uitbreiden met `totp: str | None` in de request-body en de tweestapslogica.

## Gedeelde logica

- `shared/crypto.py` — Fernet-versleuteling — bestaat ✓ (story 011)
- `vereist_api_token` + `huidige_gebruiker` uit `shared/auth.py` — bestaan ✓
- TOTP-bibliotheek: `pyotp` (PyPI) — toevoegen als dependency.
- Store-functies toevoegen aan `identiteit_toegang/store.py`:
  - `begin_2fa(gebruikersnaam)` — genereert TOTP-secret, versleutelt het, slaat op als pending (een apart kolom `totp_secret_pending_enc`), geeft `otpauth://`-URI terug.
  - `activeer_2fa(gebruikersnaam, totp_code)` — verifieert code, zet pending-secret naar actief, schakelt `totp_ingeschakeld = TRUE`.
  - `uitschakel_2fa(gebruikersnaam, totp_code)` — verifieert code, wist secret, schakelt `totp_ingeschakeld = FALSE`.
  - Uitbreiding `controleer_wachtwoord(gebruikersnaam, wachtwoord, totp_code)` — retourneert `("ok", user)` | `("totp_required", None)` | `("invalid", None)`.

## Implementatienoot

Routerlogica kopiëren en aanpassen vanuit `wetsanalyse-ai/api/app/routers/auth.py` (functies `tfa_begin`, `tfa_activate`, `tfa_disable`). De migratie voegt twee kolommen toe aan de `gebruikers`-tabel: `totp_secret_enc` (het actieve, Fernet-versleutelde secret) en `totp_ingeschakeld` (bool). Voeg optioneel `totp_secret_pending_enc` toe voor de tweestapslogica bij het koppelen (begin → activeer). De inlogstroom in Auth.js (BFF) verwerkt de `totp_required`-code door een tweede invulscherm te tonen en daarna `/v1/auth/verify` opnieuw aan te roepen met `totp`.

## UI

- **Sectie op `/account`** (story 016): "Tweestaps-authenticatie" met de status (aan/uit), een "Koppel authenticator"-knop, en (als aan) een "Uitschakelen"-knop.
- **Koppelstroom**: stap 1 — toon QR-code + handmatige code (uit de `otpauth://`-URI); stap 2 — invoerveld voor de TOTP-bevestigingscode + submit-knop "Activeren".
- **Uitschakelscherm**: eenvoudig formulier met TOTP-invoerveld + "Uitschakelen"-knop.
- **Login-flow** (in `app/login/`): na een `totp_required`-respons toont de BFF een tweede formulier met alleen het TOTP-veld.
